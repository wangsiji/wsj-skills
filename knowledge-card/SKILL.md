# 知识卡片

## 核心理念

**一张卡片，一个知识点。标题是一句话结论，不是话题，不是来源，不是问题。**

卢曼卡片盒的核心：笔记的主角是一个具体的知识结论，不是"我从哪里看来的"。一张卡片塞进多个概念，等于没有概念。

Matuschak 常青笔记的原则：标题就是程序接口——不打开正文，只看标题，就能判断这条笔记在讨论什么立场。

> **"更好的笔记"不是重点，"更好的思考"才是。**
> — Andy Matuschak

## 判断是否需要多张卡片

**一个内容可能产出多张卡片**，判断标准：

| 情况 | 操作 |
|------|------|
| 内容只讲了一个知识点 | 做一张卡片 |
| 内容讲了 N 个独立知识点 | 做 N 张卡片，每张聚焦一个结论 |
| 内容是一本书/一篇长文 | 先问用户："这张内容有几个知识点？" |

**多卡片命名示例**（同一来源，不同知识点）：
```
2026-04-21-标题-结论A.md
2026-04-21-标题-结论B.md
2026-04-21-标题-结论C.md
```

## 单张卡片格式

```
## [一句话结论/主张]

## 核心概念
【用自己的话概括，不复制原文。去掉所有例子和叙述，直接给本质。50-150字。】
【笔记主角是"这个内容在说什么"，不是"这是什么话题"。】

## 个人体验
【段落。记录被这个内容勾连起来的个人体验、感受、思考。完全私人化，越真实越好。这部分可以直接用于创作。】

## 行动指引
- [具体可执行的行动1]
- [具体可执行的行动2]
（1-3条，只在行动指引用列表）

## 参考资料
[作者] ([年份]). 作品名. 来源类型. 原文："..."
```

## 标题原则（常青笔记·API式标题）

标题是卡片的"接口"，决定了这张卡片能否被复用。

**核心要求：完整句子 + 明确立场**

| ❌ 不合格 | ✅ 合格 |
|---------|-------|
| "关于专注力的想法" | "深度工作的最小有效单位是90分钟" |
| "刻意练习书摘" | "睡眠是新记忆巩固的必要条件" |
| "什么是刻意练习？" | "刻意练习的正确框架是专注-反馈-调整" |
| "20240523-刻意练习" | "刻意练习的正确框架是..." |
| "沟通技巧笔记" | "公开场合的沉默比争辩更能建立权威感" |

**Matuschak 的判断标准**：如果写不出sharp title，通常意味着思考还不够清晰，或这张笔记在讲多件事。解决方案：先写自己最清楚的那部分。

**问题句的例外**：如果一个问题真的值得长期思考（evergreen question），可以用问句作标题。但目标是 eventually 去掉问号，改写成结论句。

**标题自检五问：**
1. 把标题发给朋友，他能看出我支持还是反对吗？
2. 这条笔记只有一个核心观点吗？
3. 时间戳/来源/模糊词从标题里清除了吗？
4. 是结论句还是问题句？（如果是问题句，它是 evergreen question 吗？）
5. 是自己的话还是原文摘录？

## 原子性原则（一张卡片只讲一个知识点）

**原则**：把相关的东西放在一起，把不同的关注点分开。—— Christian Tietze

类比软件工程的"关注点分离"（separation of concerns）：模块应该只"关于"一件事，这样更容易被复用。如果笔记太宽泛，链接会变得模糊；如果碎片化太严重，连接网络会断裂。

**两种实现方式**：
- **原子性作为输入标准**：笔记要么是原子的，要么就不该入库（过于理想化，容易造成拖延）
- **原子性作为持续目标**：不断向原子化努力，但不要求一步到位（更实用）

建议采用第二种：**不要因为达不到完美原子性就不写笔记**，而是持续迭代。

**判断标准**：这张卡片能不能被未来的多个项目复用？如果只能在一个特定场景使用，可能还不够原子。

## 笔记类型参考（Matuschak 分类法）

| 类型 | 说明 | 例子 |
|------|------|------|
| 暂存笔记 | 临时想法，还没消化 | 日常随手记 |
| 文献笔记 | 以单一作品/人物命名的笔记，主要用于链接 | "Miller - 魔术数字七加减二" |
| 常青笔记 | 概念导向，随着时间积累和进化 | "深度工作的最小有效单位是90分钟" |
| 桥接笔记 | 狭窄地连接两个相邻概念 | "无欲和有欲是同一件事的两个观察面" |
| 高级API笔记 | 抽象层次更高，综合多张笔记 | "教育游戏是创造赋能环境的失败路径" |

对于用户当前场景（道德经读书+个人成长），主要生产**常青笔记**。

## Obsidian 使用建议

**链接即思考**：每张卡片写完后，问自己："这张卡片和哪张卡片有关联？"主动建立 [[双向链接]]。

**不要用文件夹做分类**：用标签和链接来组织。文件夹是层级分类，链接是关联网络。后者更符合知识的实际结构。

**定期回顾**：每周/每月回顾最近写的卡片，检查：
- 标题还能准确反映内容吗？
- 有没有新的卡片可以链接到这张？
- 这张卡片在哪个项目/话题下被引用了？

## 常见失败模式

**"半途而废"和"想不起来"不是记笔记的问题，是系统设计的问题。**

大多数人犯的错不是"记不好"，而是：
1. 先花大量时间设计完美的分类/标签/双链系统
2. 开始记了几张
3. 觉得系统不够好，推倒重来
4. 循环往复，永远没有积累

**用户本人的真实教训（2026-05）：** Obsidian vault 里有大量 `.trash/` 文件夹和半途废弃的结构，每次都在"整理系统"而不是"积累内容"。解决方案：不要新建目录结构，直接在已有的 `20250511/` 下写卡片。

## llm-wiki 模式 vs 知识卡片模式（可共存）

Obsidian vault 可以同时承载两种模式，无需重建：

| 模式 | 触发场景 | 目录 |
|------|----------|------|
| **知识卡片** | 读完书/播客后提取卡片 | `/home/wangsiji/projects/knowledge/cards/` |
| **llm-wiki** | 深入研究一个主题（历史、地理、专题） | `/_wiki/` |

llm-wiki 的三层结构（raw/ → concepts/ → index.md + log.md）适合系统性研究；知识卡片适合随手记录阅读灵感。**不要因为想用 llm-wiki 就重建已有的 Obsidian 结构**。

**正确姿势：最小单元直接开始**

- 不要重建系统：已有的笔记、文件夹、标签体系，直接用，不要改
- 不要完美主义：先记下来，哪怕格式粗糙
- 不要回溯整理：旧的笔记不要回头改，新笔记按现在的理解写
- 不要想"以后怎么找"：双链和标签是自然生长的，不是预设的

**卡片格式应该足够简单，不用动脑就能写：**

```
## [一句话结论]

## 核心概念
（50-150字）

## 个人体验
（段落，想起什么写什么）

## 行动指引
- 具体可执行的1-3条
```

**什么时候整理：永远不主动整理。** 只有当你要用某张旧笔记时，才顺便改一下那个标题或补充内容。

## 重要原则

- **最小单元 > 完美系统**：先记一张，别管其他
- **不要重建**：已有的一切直接用，不改结构
- **不回溯**：旧笔记不回头改，新笔记按现在的理解写
- **一卡一识**：一个知识点一张卡片，不要试图在一张卡片里放进多个结论
- **原则优于清单**：遇到模糊情况，回到"这条笔记最终想说什么一句话结论"来判断
- **没有完美的命名系统**：系统要不断演进，不要追求一步到位
- **概念为导向**：不是来源、话题、时间，是知识结论本身
- **令人惊喜**：每张卡片都应该让未来的自己觉得"原来可以这么想"
- **写卡片是为了更好地思考，不是为了收集信息**
